# 计划书条款变更清单（Phase 0 之后）

计划书 `DSH_Email_Automation.md` 是 Phase 0 之前写的。经过宿主勘察与四轮界面迭代，以下条款**已被取代**。看计划书时以本表为准，未列出的条款仍然有效。

- 更新时间：2026-11-04
- 决策依据：`DSH_PLUGIN_COMPATIBILITY.md` 第 5 节

| 计划书条款 | 原文要求 | 现在 | 原因 |
|---|---|---|---|
| §1.3 | DSH UI 关闭时，邮件监听和队列仍继续工作 | **放弃**。只在 DSH 运行时同步，启动时补拉积压 | 插件的 timer / subprocess 都随 DSH 退出终止（兼容性报告 §5 D1） |
| §5.3 | 注册 `mail.message.received` 等 6 个 DSH 事件 | **不实现**。改为只读工具 + 界面主动拉取 | 宿主没有「插件向 Agent 发业务事件」的公开入口（D2） |
| §11.2 | 用 Windows 任务计划程序实现开机启动 | **不需要**。无外部常驻进程 | 同上，D1 |
| §12 | FastAPI 本机 API，127.0.0.1 + 访问令牌 | **待定 D5/D6**：若走 stdio 通道则整节不适用；若走 loopback HTTP 则保留但令牌可省 | Python Core 是插件子进程，父子管道天然可信 |
| §6.1 | 9 个一级页面（总览/收件箱/AI/草稿/审批/知识库/任务/设置/审计） | **7 个 tab 在一个面板内**：收件箱、待跟进、AI 工作台、草稿箱、审批中心、知识库、设置 | 宿主没有二级导航 slot；已实现并经截图确认 |
| §6.2 | 邮件阅读界面三栏 | **保持三栏**，两条分隔条可拖动，宽度记忆 | 已实现 |
| §6.3 | AI 工作台为「每封邮件展示摘要/分类/实体/待办」 | **改为卡片工作台**：横滑卡片，上半待处理内容、下半与 Agent 对话；处理完成归档、稍后置队尾、删除；顶栏红标显示待处理总数 | 用户界面评审定稿 |
| §6.4 | 审批卡片字段（操作类型/账户/收件人/正文/附件/影响范围/有效期） | 字段清单**保留**，落点是审批中心右栏详情 | 未变 |
| §7.1 | FastAPI + SQLAlchemy + Alembic | **待定 D6**。若纯标准库：FastAPI/SQLAlchemy/Alembic 全部不需要，改用 `sqlite3` + 手写迁移 | 自带 Python 无需安装第三方包即可满足需求 |
| §4.1 / §10.3 | 凭据用 Windows Credential Manager 或 DPAPI，DB 只存引用 | **DPAPI 加密后存 SQLite**（密文随行存储，不单独存引用） | 用户选定 D3；插件全程不接触明文 |
| §16 Phase 0 | 兼容性调查 + 最小插件 + 三项验收 | **已完成**（2026-11-04） | 见兼容性报告 §4 |

## 计划书未覆盖、但已实现的部分
